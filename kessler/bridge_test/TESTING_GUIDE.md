# Kessler Bridge Unit Tests

## Overview

Per-project tests for `out/bridge/kessler_run_bridge.py` (generated by
`workflow_bridge/phase03_make_bridge.py`), split by what they need:

| File | Needs translation? | Runs in | Gate |
|------|--------------------|---------|------|
| `test_kessler_run_bridge_layout.py` | **No** — fake pass-through kernel | Bridge workflow (`workflow_bridge/BRIDGE_WORKFLOW.md`) | Bridge generation is done only when this passes |
| `test_kessler_run_bridge.py` | **Yes** — executes `out/jax/kessler_run.py` | Translator workflow Step 4.5 (`run_bridge_tests.py --require-dependent`) | Skips itself (with reason) if translation or bridge is missing |
| `test_kessler_device_entry.py` | **Yes** — executes the real kernel through both bridge entries | Translator workflow Step 4.5, same gate | Skips itself (with reason) if translation or bridge is missing |

> **Per-project code.** Bridge tests hardcode the procedure signature,
> argument wiring order, slot indices, and physics sanity ranges of one
> scheme, so each LAFT project carries its own `bridge_test/` folder. The
> workflow docs are shared; these files are not.

## Layout contract (PATH C, device-side layout conversion — 2026-08-11)

```
Fortran side : shape (ncol, nz) — any host layout accepted; outputs come
               back standard C-order NumPy (ncol, nz)
Bridge       : pure H2D, in-jit axis reversal to (nz, ncol) around the
               jitted core, in-jit reversal back, pure D2H
JAX core side: shape (nz, ncol)
```

The array-bearing bridge imports and calls `kessler_run_core` directly —
CHARACTER args (`scheme_name`, `errmsg`) never cross the jit boundary and
pass through the bridge unchanged; `errflg` propagates numerically from the
core.

## Two bridge contracts (since 2026-08-19)

The generated `kessler_run_bridge.py` exposes the same jitted code behind
two public entries (`workflow_bridge/BRIDGE_WORKFLOW.md` §Two bridge
contracts):

- `kessler_run_bridge(...)` — **contract 1**, host-facing: NumPy in/out,
  H2D + ONE batched D2H per call (the layout contract above).
- `kessler_run_bridge_device(...)` — **contract 2**, device-resident:
  `jax.Array`s already on the device in the same Fortran `(ncol, nz)` index
  order, outputs left on the device, no transfers. No CHARACTER params
  (strings never enter the jitted region). `_kessler_run_device` remains as
  a private alias.

Contract 1 is literally `to_device → contract 2 → device_get`, so the two
are bit-identical by construction — `test_kessler_device_entry.py` proves
it against the real kernel. `kessler_init` is scalar-only and has no device
entry (nothing to keep resident).

All files run with `JAX_ENABLE_X64=1` (double precision).

## 1. Translation-independent suite (bridge-workflow gate)

```bash
cd kessler
python workflow_bridge/run_bridge_tests.py     # gate + durable report
# or, iterating on a single file:
python -m pytest bridge_test/test_kessler_run_bridge_layout.py -v
```

The runner writes the gate verdict to `out/reports/bridge/`:
`bridge_test_results.json` (top-level `status: PASS/FAIL`) and
`bridge_report.md` (generation summary + analysis warnings + per-test
outcomes). Exit code 0 = gate PASS.

Before importing the bridge, the file plants a **fake pass-through
`out.jax.kessler_run` exporting `kessler_run_core`** in `sys.modules` (and
removes it in `teardown_module`), so it runs with `out/jax/` empty — and
always uses the fake even when a real translation is present, keeping it
deterministic. The fake is called INSIDE the bridge's jitted device
wrapper, so it must stay pure/jit-traceable: it records tracer
shapes/dtypes and the concrete jit-static scalars at trace time only.
With an identity core the bridge reduces to `reverse → identity → reverse`,
so outputs must be **bit-identical** to inputs.

| Test | What it checks |
|------|---------------|
| `test_to_device_no_host_permute` / `test_roundtrip_identity` / `test_to_host_c_order` | Transfer helpers: no host-side permute, bit-exact roundtrip, float64, C-order return |
| `test_passthrough_roundtrip_identity` | All 12 outputs equal their inputs bit-exactly (every field carries unique values, so a swapped argument cannot cancel out) |
| `test_outputs_c_order_layout` | 2-D outputs `(ncol,nz)` standard C-order NumPy; `precl` `(ncol,)` |
| `test_core_receives_reversed_layout` | Inside the jit: every 2-D array arrives with reversed axes `(nz,ncol)` float64; `precl` shape unchanged |
| `test_static_scalars_concrete_at_trace` | `ncol, nz, lyr_surf, lyr_toa, errflg` reach the core as concrete jit-statics with their input values |
| `test_strings_stay_host_side` | `scheme_name`/`errmsg` never reach the core; returned as passthrough in slots 6–7; `errflg` (slot 8) a Python int |
| `test_module_vars_threaded` | `lv, pref, rhoqr` reach the core traced and return in slots 9–11 (INOUT pattern) |

If this suite fails, the defect is in the phase03 generator or the packet
metadata — see "If the test gate fails" in
`workflow_bridge/BRIDGE_WORKFLOW.md`. Never hand-edit `out/bridge/*.py`.

## 2. Translation-dependent suite (translator workflow, Step 4.5)

```bash
cd kessler
python workflow_bridge/run_bridge_tests.py --require-dependent  # the gate
# or, iterating on this file alone:
python -m pytest bridge_test/test_kessler_run_bridge.py -v
```

With `--require-dependent` the gate FAILs unless these tests run and pass —
this is the translator workflow's Step 4.5, executed after PBS runtime
validation and before the driver job (TRANSLATE_WORKFLOW.md).

Requires `out/bridge/kessler_run_bridge.py` **and** a real
`out/jax/kessler_run.py`; otherwise the whole file skips with a clear
reason. Uses synthetic, spatially-uniform atmospheric inputs
(ncol=10, nz=5, θ=300 K, qv=10 g/kg, qc=1 g/kg, qr=0.1 g/kg).

| Test | What it checks |
|------|---------------|
| `test_runs_successfully` | Bridge returns the 12 expected outputs, `errflg == 0`, shapes match |
| `test_bridge_vs_direct_jax` | Bridge matches a direct JAX call with hand-applied conversions. Arrays: `assert_array_almost_equal(..., decimal=10)` (abs diff < 1.5e-10); errflg/module vars: exact `==`; strings: bridge side asserted as passthrough (PATH C) |
| `test_driver_layout_preserved` | 2-D outputs `(ncol,nz)` standard C-order NumPy |
| `test_physics_sanity` | θ in 200–400 K; qv/qc/qr/precl ≥ 0; relhum in 0–100 % |
| `test_error_handling_negative_dt` | `dt < 0` → `errflg == 1` raised NUMERICALLY inside the core (the exact mechanism is the translation's — a `dt <= 0` flag and/or the `dt0 < 1e-12` split check); `errmsg` is CHARACTER passthrough (`''`). **PATH C behavior change (2026-08-11):** the wrapper's `if dt <= 0` guard and its `"nonpositive dt"` message do not run on the bridge path |
| `test_module_vars_inout_pattern` | `lv, pref, rhoqr` values threaded through and returned |

## 3. Contract-2 equivalence suite (translator workflow, Step 4.5)

`test_kessler_device_entry.py` — part of the same `--require-dependent`
gate as suite 2; same skip behavior. Uses physically plausible random
fields (seeded rng, ncol=10, nz=5) so a wiring defect cannot cancel out.

| Test | What it checks |
|------|---------------|
| `test_public_entry_and_alias` | `kessler_run_bridge_device` exists and `_kessler_run_device` aliases it |
| `test_device_entry_bit_identical_to_host_bridge` | contract 2 on `to_device(host inputs)` returns, after `jax.device_get`, arrays **bit-identical** to contract 1 on the same host inputs (all 6 fields + errflg + module vars); shapes/dtypes match; contract-2 outputs are `jax.Array`s (left on the device) |

## Not carried: the vertical-symmetry template

`LAFT/workflow_bridge/test_direction_symmetry.py` (added to the framework on
2026-08-25) is not part of this suite: it imports helpers from a
parameterised `test_all_bridges_layout.py` that this per-procedure suite does
not define, and it would record `n/a` for Kessler anyway — the level stride
`lyr_step` is computed inside `kessler_run`, not passed as an argument, so no
procedure qualifies. The archived gate results (17 tests) are for the three
files above.

The three files are **order-independent** under one pytest invocation: each
pops cached `out.jax.kessler_run` / `out.bridge.kessler_run_bridge` modules
before importing (fake vs real), and the layout file restores `sys.modules`
on teardown.

> **Scope.** None of these suites compares against the original **Fortran** —
> that is the end-to-end driver comparison stage
> (`out/driver/kessler_compare_fortran_jax.py`, run via
> `pbsJobs/jax_gpu_compvalues.sh`). Likewise, suite 3 proves single-call
> contract equivalence only; the *driver's* device-resident usage (arrays
> staying resident across the call sequence, one batched final fetch) is
> certified separately by running the driver + comparison pair once with
> `LAFT_DRIVER_MODE=device_resident` — done for this project 2026-08-20
> (driver PBS 7185154 + comparison PBS 7185230, bit-identical ALL PASS).

## Running on Derecho

The gates are submitted as CPU PBS jobs (the suites execute JAX, and the
framework runs every JAX step through PBS); the log lands in `out/jobs/`:

```bash
cd kessler
qsub -v TEST_SCRIPT=workflow_bridge/run_bridge_tests.py pbsJobs/jax_cpu_test.sh    # bridge workflow Step 2
qsub -v TEST_SCRIPT=workflow_bridge/run_bridge_tests.py,TEST_ARGS=--require-dependent pbsJobs/jax_cpu_test.sh    # translator Step 4.5
```

For iterating on one file from an interactive compute-node shell:

```bash
cd kessler
module load conda
conda activate jax-validate    # or your JAX environment

# bridge-workflow gate (works with empty out/jax/)
python -m pytest bridge_test/test_kessler_run_bridge_layout.py -v

# after a translation lands
python -m pytest bridge_test/test_kessler_run_bridge.py -v
python -m pytest bridge_test/test_kessler_device_entry.py -v

# or everything at once (17 tests with a translation present:
# 9 layout + 6 dependent + 2 contract-2)
python -m pytest bridge_test/ -v
```

Expected runtime: layout suite < 5 s; dependent suites < 15 s together
(includes first-call JIT).

The suites exercise whatever currently lives in `out/` — after archiving via
`tools/copy_AI_results.sh` and re-translating with another LLM, re-run them
against the new `out/` contents.

## Troubleshooting

### "Module not found"
```bash
# Run from the project root so `out.bridge` / `out.jax` import correctly
cd kessler
python3 -c "import jax; print(jax.__version__)"
```

### Numerical mismatch (translation suite)
```python
import jax
print(jax.default_backend())  # 'cpu' or 'gpu'
# Ensure JAX_ENABLE_X64=1 (set at the top of each test file)
```
